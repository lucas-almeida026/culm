This file follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Version numbers follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). `Cargo.toml` holds the version of each commit.

## [Unreleased]

### Added

- **Copy an answer as its markdown.** With the `copy-markdown` setting on, a copy of a Claude Code session hands over the copied words as the transcript holds them, from its answers, the thinking it shows, and the typed prompts: one line per paragraph, `**bold**` and `` `code` `` kept, and the list markers of the markdown in place of the bullets the panel draws. Claude Code breaks every line to fit the panel and marks none of the breaks, so a plain copy holds a line break wherever a line met the edge. Words the transcript does not hold, such as a tool line or command output, come from the screen, and a row that only met the panel edge joins the row above. A tool line that quotes an answer stays as drawn, because transcript words count only where they open a screen row. The shell copies as drawn. The setting is off by default, and `culm config set` and the settings form (`Alt+Shift+S`) change it. The status bar says `as markdown` after a copy that used the transcript. A spike on 2026-10-26 rendered one session with Claude Code 2.1.310 at 80, 120, and 200 columns and checked the release build against 1,164 simulated selections: 1,154 kept exactly their words, 930 used the transcript, and the line breaks fell from 7,479 to 6,233. The line rule alone joined no real break in 1,229 pairs of ordinary rows. A release build read and indexed the 7.9 MB transcript in 15 ms and rebuilt a selection in at most 2.1 ms. Evidence: the tests in `src/copytext.rs`, `the_markdown_copy_is_off_until_asked_for` in `src/config.rs`, and `a_markdown_copy_hands_over_the_answer_as_its_transcript_holds_it`, `a_plain_copy_keeps_the_lines_claude_code_drew`, `a_markdown_copy_without_a_transcript_still_joins_the_drawn_lines`, and `a_markdown_copy_leaves_the_shell_as_drawn` in `tests/session_lifecycle.rs`. Known gaps: an answer still streaming is not in the transcript yet, so its rows go through the line rule only. A URL after a real line break and a URL that only met the edge look the same on screen, so outside the transcript the rule can join or split it wrongly. The spike measured one session in Portuguese. A single `*` for italics is not closed when a selection cuts it.

- **Microphone for voice dictation.** Each session starts with `PULSE_SOURCE` set to a wanted microphone, so Claude Code's voice dictation records from it. culm asks `pactl -f json list sources` at each start, resume, and restore. The choice is fixed in `src/mic.rs`: a source whose name or description holds `NoiseTorch`, then one that holds `Family 17h/19h`. A monitor source never matches. With no match, or with no `pactl`, the session starts on the system default, and the status bar shows `no microphone matched. voice dictation uses the system default.` A running session keeps the source it started with, so a microphone that appears later reaches a session at its next resume. `pactl` took 6 ms on 2026-10-12. Evidence: the tests in `src/mic.rs`, and `a_session_records_from_the_wanted_microphone`, `a_session_with_no_wanted_microphone_starts_on_the_default_and_says_so`, `a_session_starts_when_the_sound_server_is_unreachable`, and `a_resume_picks_a_microphone_that_appeared_after_the_first_start` in `tests/session_lifecycle.rs`. A manual check on 2026-10-12 read this machine's `pactl` output: the pick was the NoiseTorch source, and `alsa_input.pci-0000_08_00.6.analog-stereo` without it. Known gap: no test drives voice dictation itself.
- **Delete an archived session.** In the archive list (`Alt+Shift+L`), `Alt+Shift+X` asks to delete the highlighted session, with the same question as a delete from the sidebar. The session needs no restore first. After the answer, the archive list returns. Evidence: `an_archived_session_is_deleted_from_the_archive_list_without_a_restore` and `escape_on_an_archived_delete_keeps_the_session_and_the_list` in `tests/session_lifecycle.rs`.
- **Ctrl+Enter reaches Claude Code.** A Claude Code session gets `Ctrl+Enter` as `CSI 13;5u`, which Claude Code 2.1.310 binds to "send now". The shell gets `Enter`. The key needs the kitty keyboard protocol, because the legacy path reports `Ctrl+Enter` as `Enter`. Evidence: `ctrl_enter_reaches_a_claude_session_as_its_own_key` and `ctrl_enter_in_the_shell_stays_a_plain_enter` in `tests/session_lifecycle.rs`. No test drives a real Claude Code.
- **Ctrl+z stays out of Claude Code.** Claude Code suspends itself on `Ctrl+z` with `SIGTSTP`, and inside culm no shell exists to bring it back with `fg`, so the session froze. The `block-ctrl-z` setting keeps the key from every Claude Code session, and the status bar names the setting for five seconds. The setting is on by default, and `culm config set` and the settings form (`Alt+Shift+S`) both change it. The shell always gets the key, because its job control brings a suspended job back. Claude Code 2.1.310 lists `ctrl+z` as "Unix process suspend (SIGTSTP)", checked on 2026-10-24 in the strings of the binary. Evidence: `ctrl_z_never_reaches_a_claude_session_by_default`, `ctrl_z_reaches_a_claude_session_when_the_setting_is_off`, `ctrl_z_still_reaches_the_shell`, and `space_on_the_third_setting_lets_ctrl_z_through_and_saves_it` in `tests/session_lifecycle.rs`, and `ctrl_z_is_blocked_until_asked_otherwise` in `src/config.rs`.
- **Take back a paste.** `Alt+Shift+Z` takes back the last paste in a Claude Code session, and the clipboard keeps the text, so a new paste puts it back. culm sends Claude Code's own undo, `Ctrl+_`, because culm never sees the prompt. A paste through the terminal (`Ctrl+Shift+v`), a middle click, and `Ctrl+v` all count. A spike on 2026-10-24 drove Claude Code 2.1.310 through culm's own pseudoterminal code: Claude Code merged edits 1.0 s apart into one undo step, and kept edits 1.1 s apart separate. So culm holds a paste until 1000 ms after the last input of that session, and every paste becomes one undo step. A key during the wait sends the held paste first. `Alt+Shift+Z` on a held paste drops it, and Claude Code never gets it. The same text pasted twice expands a collapsed paste, so its undo sends `Ctrl+_` twice, which the spike showed takes back the whole paste. Several pastes in a row come back one per `Alt+Shift+Z`. After a key, `Alt+Shift+Z` does nothing and the status bar says so. A paste in the shell never waits. Evidence: the tests in `src/paste.rs`, and `a_paste_right_after_typing_waits_a_second_then_reaches_claude`, `alt_shift_z_takes_back_an_expanded_paste_whole`, `alt_shift_z_on_a_waiting_paste_drops_it_and_sends_nothing`, and `ctrl_v_counts_as_a_paste_for_the_undo` in `tests/session_lifecycle.rs`. Known gaps: no test drives a real Claude Code. The spike did not cover `Ctrl+v`, because Claude Code would read the real clipboard. The same short text pasted twice also counts as an expansion, so one `Alt+Shift+Z` takes back both copies.
- **A session registers its worktrees, its ticket, and its port number.** Inside a session, `culm session worktree add <path>` records the checkout that holds the path: its top, its repository name, and its branch. `culm session worktree rm <path>` forgets it, and the worktree stays on disk. `culm session ticket <key>` records the ticket. `culm session port <0-9>` records a port number, and another session may hold the same number: the reply names it. `culm port list` prints each number from 0 to 9 and the sessions that hold it. An archived session gives its number back. `culm session show` and `culm session list` print what the sessions registered. Each session starts with `CULM_SESSION` and `CULM_PROJECT` in its environment, so these commands need no flag inside it. Outside a session, `--session` names a session by id, slug, or name, and `--project` names the project. A command for a project open in a window goes through the project's socket, and the window applies it and replies. A command for a closed project changes its file. A refused command exits with an error. At its next start, a session that registered something gets it as `--append-system-prompt`. Evidence: the tests in `src/command.rs`, `a_payload_in_the_envelope_is_a_command_and_any_other_is_a_hook` and `a_command_on_the_socket_gets_the_window_reply_back` in `src/hooks.rs`, `a_command_on_the_socket_changes_the_open_project_and_replies`, `a_command_on_an_open_project_goes_to_its_window_and_leaves_the_file`, `a_command_on_a_closed_project_writes_the_file`, `inside_a_session_the_command_line_needs_no_flag`, and `worktree_add_registers_the_top_of_the_checkout_that_holds_the_path` in `tests/browser.rs`, and `a_resumed_session_is_told_its_ticket_port_and_worktrees` in `tests/session_lifecycle.rs`. Known gap: a session started before this version gets `CULM_SESSION` at its next resume, and needs `--session` until then.
- **Adopt the worktrees sessions already use.** `culm session adopt` reads each transcript, finds the linked worktrees the session's shell stood in or wrote files in, and asks which to register for each session. `--yes` registers all of them. A main checkout is never offered, because every session shares it, and a worktree in the temporary directory is a scratch copy. On 2026-10-24, run with no pick on the maintainer's `spm` project, it read the transcripts of 28 sessions in 2.8 s with a debug build, and offered 27 worktrees to 14 of them, including four sessions whose names do not match their worktree directory. Evidence: `adopt_registers_the_linked_worktrees_a_session_worked_in` and `adopt_leaves_out_a_scratch_worktree_in_the_temporary_directory` in `tests/browser.rs`. Known gap: a separate clone in a ticket directory is a main checkout to git, so it is never offered.
- **The changes panel knows a session's own repositories.** A registered worktree is a tab before the session writes a file, and a registration while the panel is open shows at once. When the session registered a worktree, every other repository it wrote in is shared, and its "Changes" list holds only the files the session wrote, with the rest counted as `Changes (1+3)`. `a` shows every change, and `a` again goes back. The panel title names the ticket and the port number. Evidence: `a_worktree_registered_while_the_panel_is_open_appears_without_waiting_for_a_turn`, `a_shared_repository_lists_only_the_files_this_session_wrote`, `the_a_key_shows_every_change_of_a_shared_repository_and_back`, `a_session_without_worktrees_still_sees_every_change`, and `the_panel_title_names_the_ticket_and_the_port_number` in `tests/changes_panel.rs`.
- **The sidebar shows the port number.** A session row with a port number ends with `:<n>`. Evidence: `a_session_row_ends_with_its_port_number` in `src/ui.rs`.

### Changed

- **culm makes no worktree.** The new-session form asks for a name only, and every session starts at the project root. Claude Code makes the worktrees a session needs, as the project's `CLAUDE.md` says, and registers them with `culm session worktree add`. `culm project rm --recursive` removes no worktree. culm now writes nothing to git. No project file held a worktree culm made on 2026-10-24, so nothing needs a migration. A worktree registered in an older file still shows in the changes panel. Evidence: `a_new_session_starts_at_the_root_with_its_id_and_project_in_the_environment` in `tests/session_lifecycle.rs`.
- **A letter in the sidebar starts no search.** While the sidebar holds the keys, only `/` and `Alt+Shift+F` start the paused search. A letter does nothing. Evidence: `a_letter_typed_in_the_sidebar_starts_no_search` and `a_slash_in_the_sidebar_starts_the_paused_search` in `tests/session_lifecycle.rs`.
- **PageUp and PageDown scroll the panel.** Plain `PageUp` and `PageDown` scroll culm's scrollback half a panel, in a session and in the shell. A program on the alternate screen, such as vim, less, or Claude Code's fullscreen renderer, still gets the keys. Evidence: `plain_page_up_scrolls_the_history_of_a_session_on_the_main_screen` and `a_full_screen_program_pages_its_own_text` in `tests/session_lifecycle.rs`.
- **A chosen session uncovers itself.** While the changes panel is maximized, a choice of a session or of the shell closes the panel, so the choice shows. The choice is `Enter` in the sidebar or in the search, a click on a row, `Alt+0`, or a new session. A panel beside the session stays open and follows the choice. Evidence: `choosing_a_session_closes_a_maximized_panel`, `alt_zero_closes_a_maximized_panel_to_show_the_shell`, and `choosing_a_session_keeps_a_panel_beside_it_open` in `tests/changes_panel.rs`.

### Fixed

- **A copy of a scrolled Claude Code panel holds every row it covers.** Claude Code paints its own view, so the rows it scrolls off the panel never reach the `vt100` scrollback, and a selection carried off the panel copied only the rows on screen, with the prompt box and the "Jump to bottom" notice. culm now keeps every row that moved with the text while a selection rides on the scroll, and a copy reads those rows. Rows that stay in place while the text moves are left out: the prompt box, the prompt Claude Code pins to the top, and the notice at the end of a row. Each wheel notch waits until culm measured the last one, so a quick flick still lines up. A spike on 2026-10-26 scrolled one session up 120 notches in a 40 row panel: 394 of the 395 rows read back equaled a render of the whole conversation. The other row was the pinned prompt on screen at the moment of the copy. Evidence: the tests in `src/seen.rs`, and `a_selection_carried_off_a_self_scrolling_panel_copies_every_row_it_covers`, `a_copy_off_a_scrolled_claude_panel_leaves_out_what_it_draws_over_the_text`, and `a_notch_waits_while_the_last_one_is_measured` in `tests/session_lifecycle.rs`. Known gaps: a row seen only on the top row of the panel at the copy is the pinned prompt, not the text under it. A table rule near the bottom of the first panel can read as frame and come back empty. A resize drops the kept rows.

- **A rename never loses the state of an open project.** `culm project alter name` refuses a project that a culm window holds open, with `<slug> is open in culm. close its tab, then rename.`. Before the fix, the window saved under the old name, and every change after the rename went to a file that no project named. Evidence: `a_project_open_in_a_window_is_not_renamed` in `tests/browser.rs`.

## [0.2.0] - 2026-10-10

### Added

- **Changes panel.** `Alt+Shift+G` opens a read-only panel right of the session, on half of the room the sidebar leaves, and closes it. The `changes-maximized` setting opens the panel over the whole session instead. It is off by default, and `culm config set` and the settings form (`Alt+Shift+S`) both change it. A drag on the left border of the panel resizes the panel. A drag on the rule right of its list resizes the list. Each project saves both sizes, as shares in percent, in the `view` block of `projects/<slug>.json`. The list is never narrower than 20 columns and never wider than 40, so a wide or maximized panel gives the extra room to the diff. The history list holds two lists and takes eight fifths of that width. The panel shows one tab per repository of the visible session: each worktree culm made for the session, then each repository the session wrote a file in. culm reads the written files from the `Edit`, `MultiEdit`, `Write`, and `NotebookEdit` calls in the session's transcript, and asks git which repository holds each file. No layout rule is needed, so a project that keeps its worktrees anywhere, or uses none, works the same. A file outside every repository makes no tab. Two tabs with one directory name, such as a checkout and its worktree, show their path from the project root. The shell shows the repositories registered with the project. The left of the panel has two tabs, switched with `Tab` or a click. "Changes" lists every file that differs from `HEAD`: modified, new, deleted, renamed, and untracked. "History" lists the last 200 commits, and beside them the files of the picked commit. The picked file shows as a diff, the old version left and the new version right, with removed lines red, added lines green, the changed words of a line pair in a stronger color, and syntax colors from the grammars of `bat`. The panel reads git when it opens, when it follows another session, when the followed session sends `Stop`, and on `r`. `Alt+Shift+O` steps the keys through the sidebar, the session, and the panel. Evidence: `tests/changes_panel.rs`, for example `alt_shift_g_opens_the_panel_on_the_worktrees_of_the_visible_session`, `the_maximized_setting_opens_the_panel_over_the_session`, `dragging_the_list_rule_resizes_the_list_and_the_size_is_saved`, `the_panel_reads_git_again_only_when_the_followed_session_stops`, and `the_history_tab_shows_a_commit_file_against_its_parent`, and the tests in `src/diff.rs`. Syntax colors take about 0.1 ms per line in a release build: both versions of `src/app.rs`, 4,381 lines, took 431 ms on 2026-10-10. A thread computes them, so the diff shows plain first and the colors land after. Known gaps: git and the transcript read run on the interface thread, so a read stalls the frame for the time they take. A file the session changed only through a shell command makes no tab until the session also writes a file in that repository through a tool. A tab whose worktree was removed shows git's error. A file over 1 MiB shows no diff, and a file over 256 KiB shows no syntax colors.
- **Tabs.** One window opens up to eight projects, as tabs along the top. `culm open <project> <project>...` opens one tab per project, in order. A project named twice opens once. `culm` and `culm open <project>` open one tab, as before. Each tab owns its own sidebar, panel, shell, pane focus, and sidebar width. `Alt+1` to `Alt+8` and a click focus a tab. `Alt+Shift+T` opens a registered project as a new tab, from a list with its own search box. `Alt+Shift+W` closes the focused tab: its sessions stop, its project saves, and the other tabs keep running. `Alt+Shift+Left` and `Alt+Shift+Right`, or a drag along the tab bar, move a tab, and the digits follow the new order. Evidence: `tests/browser.rs`, for example `alt_and_a_digit_focus_a_tab`, `a_click_on_a_tab_focuses_it`, `closing_a_tab_stops_its_sessions_and_keeps_the_others_running`, `the_picker_lists_only_projects_not_already_open`, `alt_shift_right_moves_the_focused_tab_and_the_focus_follows_it`, and `dragging_a_tab_carries_it_past_every_tab_it_crosses`.
- **Tab markers.** Each tab shows the most urgent marker among its sessions: `🔐`, then `❓`, then `✅`. A tab with no marker keeps two blank columns. The focused tab has a yellow fill. Names shorten evenly when the row is too narrow. Evidence: `the_tab_shows_the_most_urgent_marker_of_its_sessions`, `the_focused_tab_is_filled_and_the_others_are_not`, and `a_tab_bar_too_narrow_for_every_name_shortens_them` in `tests/browser.rs`.
- **Workspaces.** A workspace names an ordered set of up to eight projects. `culm workspace new`, `list`, `show`, `add`, `remove`, `rename`, and `rm` manage workspaces. `culm open -w <name>` opens every project of a workspace. A project rename follows into every workspace, and a removed project leaves every workspace. The file is `workspaces.json`, beside `registry.json`. Evidence: the tests in `src/workspace.rs`, and `open_w_opens_the_workspace_projects_in_order` and `renaming_a_project_renames_it_in_every_workspace` in `tests/browser.rs`.
- **Save prompt on quit.** A quit with more than one project open, outside a workspace, asks whether to save the set as a new workspace. A window opened from a workspace asks only when a tab was opened, closed, or moved, and also offers to update that workspace. "Quit without saving a workspace" skips the workspace file only: every project still saves its sessions. `Esc` cancels the quit. Evidence: `two_projects_outside_a_workspace_ask_before_quitting`, `an_unchanged_workspace_quits_without_a_prompt`, `a_workspace_that_gained_a_tab_offers_an_update`, and `dont_save_writes_no_workspace_and_still_saves_every_project` in `tests/browser.rs`.
- **One project, one window.** A project already open in another culm is refused, because two windows would resume the same sessions. The other projects open. Evidence: `a_project_open_in_another_culm_is_refused_and_the_rest_open` in `tests/browser.rs`.
- **Archive.** `Alt+Shift+A` stops the focused session, active or paused, and moves it to the archive. An archived session has no row in the sidebar, and the paused search does not find it. Archiving takes no recap, whatever `recap-on-pause` says. `Alt+Shift+L` opens the archive list, newest first, with a search box of its own. `Enter` or `Alt+Shift+A` restores the highlighted session to the list it left. A session that was active resumes with `claude --resume <uuid>`. A session that was paused stays paused, with no process. A restore past the limit of nine active sessions is refused, and the session stays archived. When the transcript of a session no longer exists, a restore removes the session from the archive and the list shows the reason. Evidence: the archive tests in `tests/session_lifecycle.rs`, for example `archiving_takes_no_recap_even_when_the_setting_is_on`, `restoring_puts_an_active_session_back_in_the_active_list_and_resumes_it`, and `restoring_a_session_whose_transcript_is_gone_removes_it_and_says_why`. Known gaps: a click does not pick a row in the archive list, and an archived session cannot be deleted until it is restored. culm 0.1.1 refuses to open a project that holds an archived session, with the error `unknown variant 'archived'`. A manual check on 2026-10-10 with the 0.1.1 release binary produced that error.
- **Pane focus.** The sidebar and the panel take the keys in turn. The pane that holds the keys has a cyan border, and the other pane is dimmed. `Alt+Shift+O` moves the keys from one pane to the other. A mouse move, a drag, or a press gives the keys to the pane under the pointer, except while the separator is dragged. While the sidebar holds the keys, `Up`, `Down`, `k`, and `j` move a highlight, `Enter` shows the highlighted session, and `Esc` returns the keys to the panel. `/` or any other letter starts the paused search. No key and no paste reaches a session while the sidebar holds the keys. Evidence: the pane tests in `tests/session_lifecycle.rs`, for example `alt_shift_o_moves_the_keys_to_the_sidebar_and_back`, `the_keys_follow_the_mouse_from_one_half_to_the_other`, and `a_paste_while_the_sidebar_holds_the_keys_reaches_no_child`, and `the_half_that_holds_the_keys_has_the_accent_border` in `src/ui.rs`. Known gap: after a click on a sidebar row, the keys stay in the sidebar until the pointer moves over the panel.
- **Reorder a list by hand.** While the sidebar holds the keys, `Shift+Up` and `Shift+Down`, or `K` and `J`, move the highlighted session one row up or down its own list. A move stops at the border of a list: the first paused session does not move into the active list, and the last active session does not move into the paused list. Moving an active session changes the digit that reaches it. The order survives a restart. A session that pauses goes to the top of the paused list, so an untouched list still reads newest first. Evidence: `the_first_paused_session_never_moves_into_the_active_list`, `the_last_active_session_never_moves_past_the_active_count`, `a_hand_order_is_saved_and_survives_a_reopen`, and `a_new_pause_lands_on_top_and_leaves_the_hand_order_below_it` in `tests/session_lifecycle.rs`.

### Changed

- **Digits address tabs.** `Alt+1` to `Alt+8` focus a project tab. No digit addresses a session, and the sidebar rows show no digit. `Alt+9` reaches the child. `Alt+0` still shows the shell of the focused tab.
- **Eight active sessions per project.** The limit was nine. A project saved with more opens the first eight active and the rest paused. Evidence: `a_ninth_active_session_is_refused` and `a_project_saved_with_too_many_active_sessions_opens_the_extras_paused` in `tests/session_lifecycle.rs`.
- **Order of the paused list.** The paused list keeps the order the user gives it. culm no longer sorts the paused list by last use on every change and on every open. A session that pauses goes to the top. Evidence: `a_session_that_pauses_goes_to_the_top_of_the_paused_list` in `tests/session_lifecycle.rs`.

### Fixed

- **A quit stops a recap that is still running.** The headless recap child outlived culm and its answer was lost. Evidence: `a_quit_kills_a_recap_that_is_still_running` in `tests/session_lifecycle.rs`.

## [0.1.1] - 2026-10-10

### Added

- **Recap on pause.** The `recap-on-pause` setting keeps a short summary of what a session was doing. When a session pauses, culm runs `claude -p --no-session-persistence --resume <id> /recap` after the child exits. The panel shows the answer above `paused`. A model writes the recap, so the text changes between runs. culm skips the call when no input reached the session since the last recap. The setting is off by default, because each recap costs one model call. If the recap fails or does not answer, the panel shows `no recap was generated for this session`. Evidence: `src/recap.rs` and the recap tests in `tests/session_lifecycle.rs`, for example `pausing_keeps_what_the_session_says_it_was_doing`, `pausing_again_with_nothing_in_between_costs_no_call`, and `a_recap_that_fails_keeps_a_plain_message`.
- **Settings.** `culm config list` prints every setting. `culm config set <name> <value>` changes one setting. `Alt+Shift+S` opens the same settings in the interface, and `Space` flips a switch and writes the file at once. The file is `$XDG_CONFIG_HOME/culm/config.toml`, or `~/.config/culm/config.toml` when the variable is unset. Evidence: the tests in `src/config.rs`, and `space_flips_the_switch_and_writes_it_at_once` in `tests/session_lifecycle.rs`.
- **Closing state.** `Ctrl+q` asks every session to exit and shows a spinner until the last session is gone. culm kills a session that is still running after 3 seconds. A second `Ctrl+q` kills every session at once. The next open of the project shows `recovered from forced quit` on the bar for 5 seconds. No key reaches a session while culm closes. Evidence: `a_child_that_ignores_the_request_is_killed_once_the_grace_runs_out`, `a_second_quit_cuts_the_wait_short_and_is_recorded`, and `no_key_reaches_a_child_while_the_interface_closes` in `tests/session_lifecycle.rs`.
- **Sidebar width per project.** Each project saves its sidebar width in the `view` block of `projects/<slug>.json`. The project opens at the saved width. A width outside 20 to 60 columns is clamped to the nearest limit. A project with no saved width opens at 30 columns. Evidence: `the_width_survives_a_quit_and_a_reopen` and `a_stored_width_outside_the_limits_opens_clamped` in `tests/session_lifecycle.rs`.
- **Extend a selection.** `Alt` and a click move the end of the selection to the click point and keep the anchor. Two gestures copy a block taller than the panel. Evidence: `alt_click_extends_the_selection_instead_of_starting_a_new_one` in `tests/session_lifecycle.rs`.

### Fixed

- **A selection stays on its text when the panel scrolls.** The wheel and `Shift+PageUp` move the selection by the distance the text moved. A session that scrolls itself, such as Claude Code, reports no distance. For such a session, culm compares the panel rows before and after the scroll and moves the selection by the matched offset. If the rows do not match, culm drops the selection. Evidence: `the_wheel_carries_the_selection_with_the_text_it_marks` and `a_forwarded_wheel_drops_the_selection_when_the_child_drew_a_fresh_screen` in `tests/session_lifecycle.rs`. Known gap: culm cannot copy text that a self-scrolling session moved off its panel.
- **Home, End, and the arrow keys follow the cursor key mode of the child.** A shell line editor such as zsh switches the terminal to application cursor mode and binds `ESC O H` to Home. culm reads the mode from the screen of the child and sends `ESC O H` and `ESC O F` in that mode. `Shift` and `Ctrl` now reach the child with Home and End, as `ESC [ 1 ; 2 H` and `ESC [ 1 ; 5 F`. Evidence: `home_and_end_reach_a_shell_line_editor_in_its_own_mode` in `tests/session_lifecycle.rs`, and the cursor key tests in `src/keys.rs`.
- **`Ctrl+Backspace` deletes the word before the cursor.** culm sends `ESC DEL`, the same bytes as `Alt+Backspace`. zsh and bash bind `ESC DEL` to `backward-kill-word` by default. Claude Code 2.1.296 deletes a word on the same bytes. In the insert mode of vim, the `ESC` byte leaves insert mode. Evidence: `control_backspace_deletes_a_word_instead_of_a_character` in `src/keys.rs`.
